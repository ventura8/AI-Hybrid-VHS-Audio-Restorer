# AI Hybrid VHS Audio Restorer v1.3.1 - Model Names Stay Inside the Model Store

## Highlights

A patch release: one security fix in the model loader, a dependency refresh
that clears a second advisory, and no change to restoration output.

- A model filename taken from `config.yaml` could reach the model store's
  purge-and-retry path unsanitised. `audio-separator` rejects a name it does
  not know, the loader treated that as a corrupt download and unlinked
  `models/<name>`, and `pathlib` lets an absolute path or a `..` segment
  escape the directory. A planted `config.yaml` in the launch directory --
  which is read ahead of the bundled one -- could therefore delete any file
  the process can write, in the default mode, while the pipeline fell back
  and still produced a cleaned video.
- Every UVR model setting is now reduced to a bare filename at load time,
  and the purge refuses any path that does not resolve to a file directly
  inside `models/`. Both halves are tested with the traversal payloads that
  were used to confirm the issue.
- `accelerate` moves from 1.14.0 to 1.15.0, past CVE-2026-69112
  (PYSEC-2026-3804): a path traversal through sharded checkpoint
  `weight_map` entries, which `pip-audit` had begun failing the gate on.
  tqdm, matplotlib, coverage, ruff and pymarkdownlnt move to their latest
  final releases in the same lock; the torch, onnxruntime and transformers
  bumps are deferred (see Dependencies), and the GitHub Actions and Poetry
  pins were already current.
- The workspace skills under `.agents/skills/` are now invocable from Claude
  Code through a pointer catalog in `.claude/skills/`, and `prepare-release`
  is rewritten around the release procedure this repository actually
  follows.

## The fix

**Where the name came from.** `apl_neural_model` was stored as a stripped
string; `vocals_model` and `denoise_model` were stored raw. All three flow
into `_load_separator_model`, whose failure path calls
`_purge_corrupted_model_file(model_name)`. The report named only
`apl_neural_model`; the other two reach the same sink and were closed in the
same pass. `background_model` is validated the same way for consistency, but
no mode reads it, so it was never an affected setting.

**Sanitised at the source** (`modules/config.py`). A new
`_model_filename(setting, value, default)` accepts a bare filename string
and nothing else: a non-string YAML value (`true`, `42`, a list), a value
containing `/` or `\`, a `.`/`..` name, a leading dot, or a NUL byte is
refused with a warning on stderr naming the setting, and the default is used
instead; unset and empty fall back silently. The vocals and background
defaults are hoisted to `DEFAULT_VOCALS_MODEL` and `DEFAULT_BACKGROUND_MODEL`
so the fallback and `_typed_config_defaults()` share one value.

**Confined at the sink** (`modules/processing.py`).
`_purge_corrupted_model_file` resolves `MODELS_DIR / model_name` and unlinks
only when the resolved parent is the resolved model store. This holds even
for a caller that bypasses config, and it is the layer that makes the
traversal impossible rather than merely unlikely.

**Behaviour a user can see.** A working configuration is unaffected: every
shipped model name is a bare filename. A configuration that set a model to a
path never worked -- the name was rejected by `audio-separator` -- and now
also logs why and falls back cleanly instead of deleting something.

Each of these is a bump whose runtime requirements (`requires_dist` outside
any extra, and `requires_python`) are identical to the locked version's; the
one metadata change, `accelerate` adding `peft` to its optional `dev`,
`test-dev` and `testing` extras, is carried into `[package.extras]`. The
lock entries were rewritten from the PyPI release metadata with the
content-hash recomputed by Poetry, and verified by `poetry check --lock` and a
hash-checked `poetry install`.

**Deferred: torch 2.14.0 / torchvision 0.29.0, onnxruntime 1.30,
transformers 5.17.0.** The newest matched set is on the `cu130` index and the
pins are ready, but Poetry 2.4.x cannot regenerate this lock: the torch
multiple-constraint entries, the `cuda-toolkit` 13.0.3 extras and pandas's
`tzdata` marker send its override loop into a combinatorial re-solve that
stalls after round 79 on every attempt (the CI note above "Verify Poetry
Lockfile" records the same behaviour at six hours). A targeted
`poetry update` of a single light package stalls at the same round. Those
four bumps wait for a resolver that finishes; the lock stays on torch 2.13.0
/ torchvision 0.28.0 / torchaudio 2.11.0, onnxruntime 1.29 and transformers
5.16.1, all of which are current for this project's purposes.

Actions pins (`checkout` v7.0.1, `setup-python` v7.0.0, `upload-artifact`
v7.0.1, `download-artifact` v8.0.1, `action-gh-release` v3.0.3) and Poetry
2.4.3 were verified against their latest releases and left as they are.

## Upgrade Notes

No configuration change is required for a valid bare-filename setting,
which every shipped model name is. If your `config.yaml` sets
`vocals_model`, `denoise_model` or `apl_neural_model` (or the currently
unused `background_model`) to
anything other than a bare filename, the setting is now ignored with a
warning and the default is used; put the model file in `models/` and name
it by filename alone. `docs/configuration.md` has a new "Model Files"
section with the rule.

Restoration output is unchanged in every mode. Re-run
`./install_dependencies.sh` (or `.ps1`) to pick up the refreshed lock; the
torch trio is unchanged.
