# AI Hybrid VHS Audio Restorer v1.3.3 - Nothing Left Behind, Resume After Power Loss

## Highlights

A patch release about temp and file hygiene: every stage now publishes its
file atomically, the final render is staged inside the work directory, a
resumed run sweeps the partials an interrupted run left, and the process's
temp locations are confined to the work directory. Restoration output is
unchanged: `cathar` is bit-identical to the v1.3.1 build on all five
reference clips, and a run cut off three times and resumed produces the same
decoded audio as an uninterrupted run.

- **Partials could be resumed as finished stages.** Seven stages streamed
  straight into their target file: the FFmpeg polish, de-esser and expander
  renders, the pop repair, the hum and tone cancellers, the plosive tamer,
  the native spectral suppressor, DeepFilterNet and the learned blend. A
  power cut mid-write leaves a WAV whose header still reads as valid audio
  (a test confirms a file truncated to a third passes `is_valid_audio`), so
  the next run would have taken the fragment for the whole and carried it
  through to the output. Every one of them now writes through
  `atomic_target()` and publishes with one rename.
- **The final render bled next to the source.** The mux wrote
  `<name>_Cleaned.tmp.<ext>` beside the video and renamed it on success; an
  interruption left that file outside the work directory. It is now staged
  inside `.temp_work_<video>/` and moved into place only once verified.
- **A skipped task never tidied up.** A run cut off between publishing the
  output and removing its work directory left that directory forever: the
  next run saw the output, skipped the task, and returned before cleanup.
  The skip path now removes a stale work directory too.
- **Partials are swept on resume.** Reopening a work directory removes every
  unpublished partial (`*.tmp.*` and the dot-prefixed same-directory temp
  `audio-separator` leaves), so no stage can glob one as its own output.
- **Temp is confined.** While a video is processed, Python's `tempfile` and
  the `TMP`/`TEMP`/`TMPDIR` variables every child process inherits point at
  `.temp_work_<video>/tmp`, so library scratch leaves with the work
  directory instead of accumulating in the system temp.
- **Windows cleanup retries.** Removing the work directory retries briefly
  for handles the OS releases late and warns when it cannot, instead of
  failing silently.
- **The session log is capped.** `session_log.txt` grew without bound (53 MB
  on the development machine); it now rotates at 10 MB, keeping one previous
  generation.
- The launcher no longer creates an unused `output/` folder in the launch
  directory; restored videos have always been written next to their source.

## Verification

- Default mode on `E:\Test` (two captures): only the two `*_Cleaned` files
  appeared next to the sources; no work directory, no file in the launch
  directory beyond `session_log.txt`, nothing new in the system temp.
- Simulated power loss on the default mode, killed during a partial write,
  two seconds into a later stage, and while the final render was staged: the
  partial left each time was removed on the next start with a `[Hygiene]`
  log line, nothing was ever left beside the source, and the resumed output
  decoded identically to an uninterrupted run.
- Every other mode was run on the same folder with a filesystem snapshot
  before and after; the findings are in the pull request.
- `cathar` identity: 5 of 5 reference clips decode bit-identically to the
  v1.3.1 outputs.
- Quality gate: 1078 tests, 95.02% total coverage, every file at or above
  90%, Radon CC and MI grade A, ruff / black / isort / flake8 / pylint /
  bandit clean.

## Upgrade Notes

No configuration change. A work directory left by an earlier build is
resumed and cleaned by this one. The launch directory may still contain an
empty `output/` folder from earlier builds; it is safe to delete.
