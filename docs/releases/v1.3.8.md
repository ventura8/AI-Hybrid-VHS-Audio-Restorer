# v1.3.8

v1.3.7 was tagged but never published: its release build failed on Windows. v1.3.8
ships everything below plus that fix.

## Highlights

`auto_pure_linear` loses the thin 's' the third listening round heard, by a
change made by ear, and the repository passes SonarQube Cloud with no open
issue on any branch: 196 findings from main's first full analysis are fixed at
the source, no suppressions.

- **The air shelf at +1 dB.** `auto_pure_linear`'s presence shelf at 7.5 kHz
  (`linear_air_gain_db`) drops from +2 dB to +1 dB.
- **Command-line values are checked where they are used.** Every argument
  Sonar traced to a file or a subprocess, plus the quality scorer and the
  listening-set renderer, is confined to the repository, the temp directory
  or a root listed in `AI_RESTORE_DATA_ROOTS`, and numbers and names are
  rebuilt before they reach a subprocess. About 18 analysis scripts still take
  plain paths that reach no traced sink.
- **SonarQube Cloud: gate OK, 0 issues, 95.9% coverage on main.**
- **The tuning loop skips knobs that cannot move the audio**, and the sibilant
  guard's fricative detector threshold is a setting and a loop knob.

## The thin 's' on `auto_pure_linear`

The second listening round accepted everything the self-driving loops chose
except one thing: `auto_pure_linear`'s 's' sounded thin. Two loop passes on
the sibilant guard plateaued without an audible change: their finals differed
from what the user heard by -70 to -100 dBFS, because the guard's fricative
detector (a hop's share of energy above 4 kHz of at least 0.5) caught 3
fricatives in five minutes of Vaccin where the harness found 30. Tape rolls
the highs off, so a real 's' rarely puts half its energy above 4 kHz.

Measured on the same fricatives, the denoiser leaves the 's' within 1 dB of
the rest of the speech in every band from 250 Hz to 12 kHz. What brightens it
is the presence shelf, which lifted the whole output about 1.6 dB above 4 kHz.
The harness's `sibilance_thin` reading is net of the plain loud frames, so a
tilt that raises every frame's top does not register, and the loops kept
+2 dB. In an A/B of +2 dB, +1 dB and off on the four Tata tapes the user chose
+1 dB: 8-12 kHz about 0.7 dB lower, 4-8 kHz about 0.3 dB, nothing below 4 kHz
moved. Only `auto_pure_linear` applies the shelf.

The guard's detector threshold is now `apl_sibilant_hf_share_min` (default
0.5, output unchanged), a knob the loop searches, since at 0.3 the detector
covers 82% of the harness's fricatives instead of 12.5%.

## SonarQube Cloud

Pull-request scans judge new code only; main's first analysis, after the
v1.3.3 merge, judged the whole repository and failed the quality gate on 196
issues. All are fixed:

- **33 vulnerabilities** (command-line arguments reaching a file write or a
  subprocess unchecked, `pythonsecurity:S8705/S8707`). Validation inside an
  argparse `type=` is invisible to Sonar's taint analysis, which starts at
  `parse_args()`, so every value is checked at the use site:
  `scripts/cli_paths.py` adds `confined_path()` (refuses an option-shaped
  value, resolves, and requires the path to lie inside the repository, the
  temp directory or a root in `AI_RESTORE_DATA_ROOTS`), `checked_number()`
  (rebuilt with the script's own type and range-checked), `checked_token()`
  and `checked_url()`. A crafted `--report -rf` or `--start "-i /etc/passwd"`
  is now refused before it reaches ffmpeg or the file system.
  `scripts/validate_restoration.py` confines every path it takes, and the
  tuning loop passes it each tape's folder.
  `scripts/test_installed_executable.py` carries the same check locally, and
  the release workflow lists each platform's install directory in
  `AI_RESTORE_DATA_ROOTS`.
- **70 test findings**: composite assertions split, over shared builders where
  radon's limit requires it; `monkeypatch` instead of attribute assignment.
- **30 module findings**, pure refactors (constants for repeated literals,
  `RuntimeError` instead of `Exception`, unused parameters dropped,
  `atomic_target`'s cleanup in `try/finally`); `cathar` decodes bit-identically
  to the v1.3.3 reference on all five clips.
- **29 shell findings** (`[[ ]]` tests, default `case` branches) and **34
  further script findings** (cognitive complexity, merged f-strings, a regex
  without super-linear backtracking, redundant exception classes).

## Tuning loop

- Knobs a switch makes inert (the subtraction stage's settings while the stage
  is off, the stem path's settings while the stem path is off) are no longer
  proposed; a round went from 30 candidates to 21.
- `auto_pure_linear` reads its own expander depth (`apl_expander_depth_db`),
  so the loop tunes that key instead of the shared one.
- The loop launchers write their completion marker only when the loop
  succeeded; the listening-set builders are committed and refuse to publish a
  set with a missing candidate.

## The v1.3.7 release build

The installed-app smoke test checked that `--config-dir` exists while parsing its
arguments. The Windows step removes the install directory first and the installer
creates it during the test, so the run stopped before installing and v1.3.7 was not
published. The directory is now resolved at parse time and checked where `config.yaml`
is read; a test covers a directory that does not exist yet.

## Upgrade Notes

`auto_pure_linear` (and `auto`, which runs it on most material) is 0.7-1 dB
darker above 8 kHz than in v1.3.3; set `linear_air_gain_db: 2.0` to keep the
earlier brightness. `cathar` output is unchanged.

The developer scripts under `scripts/` refuse a path outside the repository
and the temp directory unless its root is listed in `AI_RESTORE_DATA_ROOTS`
(separated by the platform's path separator), for example
`AI_RESTORE_DATA_ROOTS=D:\Tata` to measure tapes on another drive. The
restorer itself is not affected.
