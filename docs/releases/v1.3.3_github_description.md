# v1.3.3

## Highlights

`auto` now chooses between `auto_pure_linear` and `cathar` on the evidence of
the real-tape corpus, and its acoustic profile block prints every measure the
choice rests on. Engine output is unchanged (`cathar` bit-identical on all
five reference clips).

- `auto` never ran the two engines this project measures. Its three former
  engines leave the noise on the tape (0.11, 0.35 and 0.72 dB of noise removed
  over 136 clips, against 10.10 for `auto_pure_linear` and 6.02 for `cathar`).
- `auto` is the default. Every acoustic class runs `auto_pure_linear`,
  which leads `cathar` on each one, on the corpus and on 81 excerpts of 21
  local tapes; `cathar` runs on sustained tonal programme with no silence
  for the noise probe -- the one condition, of some thirty readings scored
  on both sets, under which it deviates less on most clips, for 2-3 dB less
  removal (`auto_cathar_tonal`) -- and where the neural denoiser is not
  installed.
- The profile block adds rhythm, spectral flatness (the chain's own tonal
  gate), the mains notch, the material class, the verdict with its numbers,
  and both engines with whether each is installed.
- `enable_multipass` is no longer read; `multipass_auto` stays one
  `process_mode` away.

## Verification

Every engine `auto` could dispatch measured on the same 136 clips with the
same trade metric; hardware validation of the new dispatch on the RTX 5090
(`auto` mid fixture 6.01x, 18,715 MB); `cathar` 5 of 5 bit-identical;
1164 tests at 95.34% coverage with every gate green.

## Upgrade Notes

`auto` is the default `process_mode`; an existing `config.yaml` keeps the
mode it names. `auto` output comes from the `auto_pure_linear` chain under
the `*_Auto_Cleaned` name (or `cathar` on tonal programme without silence);
set `process_mode` to `multipass_auto` to keep the earlier dialogue
behaviour, `auto_cathar_tonal` to false to keep `auto_pure_linear` on tonal
programme.
