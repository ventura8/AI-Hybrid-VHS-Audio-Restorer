# AI Hybrid VHS Audio Restorer v1.3.3 - Nothing Left Behind, Resume After Power Loss

## Highlights

A patch release about temp and file hygiene; restoration output is
unchanged (`cathar` bit-identical on all five reference clips).

- Seven stages streamed straight into their target file, and a WAV cut off
  mid-write still reads as valid audio, so a rerun after a power loss could
  resume from a fragment. Every stage now writes a same-directory partial
  and publishes it with one rename.
- The final render was staged beside the source video; it is now staged
  inside `.temp_work_<video>/` and moved into place once verified.
- A run cut off between publishing its output and cleanup left its work
  directory forever; the skip path now removes it.
- Partials are swept whenever a work directory is reopened, the process's
  temp locations (`tempfile`, `TMP`/`TEMP`/`TMPDIR`) point inside the work
  directory while a video is processed, Windows cleanup retries late-released
  handles, and `session_log.txt` rotates at 10 MB.

## Verification

Default mode and every other mode run on a real capture folder with
filesystem snapshots before and after; a run killed at three stages and
resumed decodes identically to an uninterrupted run; 1078 tests at 95%
coverage with every gate green.

## Upgrade Notes

No configuration change. An older build's leftover work directory is resumed
and cleaned by this one.
