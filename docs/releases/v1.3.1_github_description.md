# AI Hybrid VHS Audio Restorer v1.3.1 - Model Names Stay Inside the Model Store

## Highlights

A patch release: one security fix in the model loader, a dependency refresh
that clears a second advisory, and no change to restoration output.

- A model filename from `config.yaml` (`apl_neural_model`, and likewise
  `vocals_model` and `denoise_model`) reached the model
  store's purge-and-retry path unsanitised. When `audio-separator` rejected
  the name, the loader treated it as a corrupt download and unlinked
  `models/<name>` -- and an absolute path or `..` segment escaped the
  directory. A `config.yaml` planted in the launch directory could delete
  any file the process can write, in the default mode, while restoration
  fell back and still produced output.

- Model settings are now reduced to a bare filename at load time (anything
  else is ignored with a warning and the default is used), and the purge
  refuses any path that does not resolve to a file directly inside
  `models/`. Both layers are tested with the traversal payloads used to
  confirm the issue.

- `accelerate` 1.14.0 -> 1.15.0 clears CVE-2026-69112 (sharded checkpoint
  path traversal); tqdm, matplotlib, coverage, ruff and pymarkdownlnt move
  to their latest final releases. The torch / onnxruntime / transformers
  bumps are deferred: Poetry's resolver cannot regenerate this lock's torch
  multiple-constraint set (details in `docs/releases/v1.3.1.md`).

## Upgrade Notes

No configuration change is required for a working setup. A model setting
that is not a bare filename is now ignored with a stderr warning rather than
passed through; see the new "Model Files" section in
`docs/configuration.md`. Re-run `./install_dependencies.sh` (or `.ps1`) to
pick up the refreshed lock.
