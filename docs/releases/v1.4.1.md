## The scanner's memory (issue #14)

`auto` profiles at most 240 s of audio (four 60 s blocks of a long file). On
that input `tracemalloc` measured 593 MB for the spectral flatness reading
and 140 MB for the probe-similarity reading. scipy's `stft` pads a float32
signal with float64 zeros and windows it with a complex64 window, so it held
a complex128 copy of every overlapping segment; `welch` held every frame's
spectrum beside its periodogram; and the loud-frame selection squared the
whole signal at once.

The routing thresholds (`auto_cathar_flatness_max`,
`auto_cathar_probe_similarity`) and `auto_pure_linear`'s tonal gate were
calibrated on the numbers those calls produce, so nothing is approximated.
`modules/lean_spectra.py` runs scipy's own arithmetic on a block of 256
frames at a time and keeps only what a reading needs: the 100-5000 Hz rows
for the flatness, the periodogram for the probe. The reductions run on an
array laid out the way scipy's is, so every mean sums in the same order. The
loud frames' levels are read 2048 rows at a time.

| Reading | Before | After | Target (issue) |
|---|---|---|---|
| `_estimate_tonality` | 593 MB | 48 MB | under 150 MB |
| `_probe_programme_similarity` | 140 MB | 59 MB | under 100 MB |

Checked old against new, bit for bit, on the 136 Internet Archive clips the
routing rule was measured on, the five `cathar` identity clips, 81 one-minute
excerpts of local captures and the four Tata tapes. Each check covered the
loud-frame selection, the unrounded flatness, the loud frames' periodogram,
the unrounded probe correlation and the scanner's whole profile, at the
256-frame block and at a 7-frame block, so 15 s clips cross many blocks too:
226 of 226 equal. `tests/unit/test_lean_spectra.py` compares the blocks with
scipy itself on float32 and float64 input and on odd frame lengths, and
measures both peaks on a 240 s input; a scipy release that changes either
code path fails it.

## Release assets

A `.deb` built for v1.1.0 had been committed under `release-assets/`, a
folder ignored since. The publish job checks out the tag, downloads the
platform artifacts into that folder and uploaded `release-assets/*`, so the
stale package rode along on every release. The file is no longer tracked,
and the publish step uploads only `AI-Hybrid-VHS-Audio-Restorer-<tag>-*`.

### torch 2.15.0, held

The cu130 index ends at torch 2.14.1; torch 2.15.0 (2026-10-28) comes with a
matched torchvision 0.29.2 and torchaudio 2.11.1 on cu132 only. Locked and
installed, it renders `auto_pure_linear` the same way run after run, but not
the way 2.14.1 does. On the three APL identity clips the difference reads
-53.7 to -58.8 dB under the loud frames, and `scripts/audibility_check.py`
reads all three audible (up to 13 frames at +6 dB over the masked threshold,
a noise-to-mask ratio up to 15.2 dB). Swapping only the torch set back to
2.14.1, with every other new package in place, renders 3 of 3 identical, so
the change is torch's. A dependency that moves the restored audio this much
needs the realistic-v2 and IA confirmation and the listening session a
changed default needs, so the set stays at 2.14.1+cu130 and 2.15.0 comes in
a change of its own (cu132 source, `nvidia-cublas` 13.4.1.3,
`nvidia-cuda-nvrtc` 13.2.86). `cathar` never loads torch.
